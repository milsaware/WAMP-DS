# Development Entry #02 - Project Root Context Menu Missing

**Date:** 16 August 2026  
**Area:** Project Explorer  
**Type:** Bug Fix  
**Status:** Fixed

---

## The Problem

The next issue discovered while using WAMP-DS was found in the Project Explorer.

While working on the missing `assets` directory described in Development Entry #01, the instinctive solution was to right-click the project root and create the required folder manually.

However, right-clicking the project root did nothing.

There was no context menu and therefore no way to create a new file or folder directly inside the root of the project.

This was particularly noticeable because the Project Explorer already supported context menus for directories further down the project tree.

The root folder was therefore behaving differently from the directories it contained.

---

## How It Was Discovered

The issue was discovered while investigating the missing `assets` directory from the previous development entry.

After noticing that the directory had not been created automatically, the immediate instinct was simply to create it manually through the Project Explorer.

The project root was right-clicked.

Nothing happened.

There was no:

    📄 New File
    📁 New Folder

menu.

This was a very natural interaction.

When working with a project tree, right-clicking the root folder to create a new folder is exactly what a developer would reasonably expect to do.

The fact that this didn't work exposed another small gap in the Project Explorer.

Interestingly, this issue was discovered **before the assets-directory bug was fixed**, meaning the two bugs were encountered almost one after another during the same piece of real development work.

---

## Investigation

The Project Explorer was traced through the tree creation code in `MainWindow`.

Individual project items were created by `CreateTreeViewItem()`.

That method created the visual tree item, added the appropriate folder or file icon, populated child items for directories, and assigned the Explorer context menu:

```csharp
treeItem.ContextMenu = CreateExplorerContextMenu(item);
```

The context menu itself was generated by:

```csharp
CreateExplorerContextMenu(ProjectItem item)
```

For normal project directories, this worked correctly because each directory was represented by a `ProjectItem`.

The project root, however, was created separately inside `RefreshProjectTree()`.

The root `TreeViewItem` was created directly:

```csharp
TreeViewItem projectTreeItem = new()
{
    Tag = projectManager.CurrentProjectPath,

    Foreground = new System.Windows.Media.SolidColorBrush
    (
        System.Windows.Media.Color.FromRgb(
            204,
            204,
            204
        )
    )
};
```

The root was then given its own header containing the folder icon and project name.

However, unlike the normal project items, no context menu was assigned to it.

The result was that the root looked and behaved like a directory visually, but did not have the directory actions available to it.

---

## The Fix

The project root was given its own Explorer context menu.

Because the root is represented by the project path rather than a `ProjectItem`, the root-specific menu actions operate directly against:

```csharp
projectManager.CurrentProjectPath
```

The root context menu now provides:

    📄 New File
    📁 New Folder

These actions use the existing `CreateNewExplorerFile()` and `CreateNewExplorerFolder()` functionality.

The existing context menus for normal directories were left unchanged.

This keeps the implementation simple while ensuring that the project root behaves like the directory it represents.

---

## Verification

The Project Explorer was refreshed and the project root was right-clicked.

The context menu now appears correctly.

A new file can be created directly in the project root.

A new folder can also be created directly in the project root.

Existing directories continue to provide their own context menus.

Files continue to provide their existing:

    ✏ Open
    🗑 Delete

options.

The Project Explorer now provides the expected context-menu behaviour throughout the project hierarchy.

---

## Result

This was another small issue that only became obvious through actual use of WAMP-DS.

The functionality for creating files and folders already existed.

The functionality for displaying project directories already existed.

The problem was simply that the project root was constructed separately from the normal `ProjectItem` tree and had never been given the same context-menu functionality.

It was an easy thing to overlook during development because the rest of the Explorer behaved correctly.

But when actually working with a project, the root directory is the first place a developer naturally expects to be able to create something.

A right-click.

Nothing.

A quick investigation.

A small fix.

And the Project Explorer became a little more like the development environment it was supposed to be. 😄
