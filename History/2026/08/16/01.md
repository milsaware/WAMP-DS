# Development Entry #01 - Assets Directory Not Created

**Date:** 16 August 2026  
**Area:** Project Creation  
**Type:** Bug Fix  
**Status:** Fixed

---

## The Problem

The first issue discovered while using WAMP-DS for actual development was encountered when creating a new blank HTML project.

The project itself was created successfully, but the expected `assets` directory was missing.

This was particularly noticeable while working on a small game, where an assets directory was needed for project resources.

The intended starter project structure already included a basic CSS file and JavaScript file, but these were not being created either.

So although project creation was technically succeeding, it wasn't producing the complete starter structure expected from a new WAMP-DS project.

And, rather annoyingly, this hadn't been obvious while developing the project creation system itself.

---

## How It Was Discovered

The issue was discovered while using WAMP-DS to create **Emoji Dash**, a small Boulder Dash-style game.

This wasn't a deliberately constructed test case. It was simply the result of using WAMP-DS as it was intended to be used: as a development environment.

A new blank HTML project was created and its structure was inspected.

The `assets` directory wasn't there.

That immediately exposed something that hadn't shown up during development: the project creation workflow was being tested as a feature, but it hadn't yet been tested through the eyes of someone actually using the application to build something.

This was the first real example of WAMP-DS finding its own bugs through normal use.

---

## Investigation

The project creation process was traced through `ProjectCreationManager` and into `ProjectManager`.

During the investigation, it became clear that the code required to create the standard project files **already existed**.

`ProjectManager` contained a `CreateProjectFiles()` method which created:

    assets/
    ├── style/
    │   └── style.css
    └── js/
        └── script.js

It also created the initial HTML or PHP file and populated the starter CSS and JavaScript.

The problem was that `CreateProject()` was not calling `CreateProjectFiles()` for new HTML and PHP projects.

Instead, it was calling `CreateHtmlProject()` or `CreatePhpProject()` directly.

The functionality was therefore already present — the normal project creation path was simply bypassing it.

---

## The Fix

The project creation workflow was changed so that new HTML and PHP projects use the existing `CreateProjectFiles()` method.

This means the standard project scaffold is now created automatically when a new project is initialised.

A new HTML or PHP project now receives:

    Project/
    ├── assets/
    │   ├── style/
    │   │   └── style.css
    │   └── js/
    │       └── script.js
    ├── index.html / index.php
    └── settings.wampds

The generated stylesheet provides a basic starting point, while the JavaScript file contains an initial console message:

    console.log("WAMP-DS project ready.");

The existing HTML and PHP templates already reference these files, so the generated project is immediately wired up and ready to start developing.

Framework-based projects such as Laravel and CodeIgniter were left to their respective installation managers rather than applying the generic project scaffold to them.

---

## Verification

A new blank HTML project was created after the change.

The resulting project structure was checked and the `assets` directory was present automatically, along with the starter CSS and JavaScript files.

The generated HTML file correctly referenced both files.

A PHP project was also checked to ensure that it received the same standard project resources.

The project creation workflow now creates the expected starter structure without requiring the developer to manually create the assets directory or its initial files.

---

## Result

The first real-world issue found while using WAMP-DS was a small one, but it highlighted something important.

The project creation system wasn't fundamentally missing the functionality — it already had the code required to create the assets structure. The problem was that the normal creation workflow wasn't actually using it.

This is exactly the sort of issue that can remain hidden during development and immediately reveal itself once the software is used for real work.

The fix brings the generated HTML and PHP project structure in line with the intended development workflow.

One missing folder.

A couple of missing starter files.

One small fix.

And the first page in WAMP-DS's real-world development history. 😄
