# Development Entry #03 - New Project Preview Not Loading Automatically

**Date:** 16 August 2026  
**Area:** Project Creation / Live Preview  
**Type:** Bug Fix  
**Status:** Fixed

---

## The Problem

The next issue discovered while using WAMP-DS was found in the transition between project creation and the Live Preview.

When a new project was created successfully, the Project Explorer updated correctly and displayed the newly created project.

However, the docked Live Preview did not automatically load the new project.

The project had been created.

The project had been opened by the `ProjectManager`.

The Project Explorer had been refreshed.

But the Live Preview remained unchanged.

This meant that after creating a new project, the developer had to take an additional action before seeing the new project in the preview.

The expected behaviour was that creating a project would leave WAMP-DS ready to work on it immediately, including loading its preview.

---

## How It Was Discovered

The issue was discovered while using WAMP-DS through the normal project creation workflow.

A new project was created and the creation process completed successfully.

The Project Explorer updated as expected and displayed the new project structure.

However, the docked Live Preview did not change.

The preview still showed the previous state instead of automatically loading the newly created project.

This was another example of an issue that was not immediately obvious from looking at the individual systems in isolation.

Project creation was working.

The Project Explorer was working.

The Live Preview was working.

The problem was that the final step connecting those systems together was missing.

The expected workflow was:

    Create Project
        ↓
    Project Created
        ↓
    Project Explorer Updates
        ↓
    Live Preview Loads New Project

Instead, the actual workflow was:

    Create Project
        ↓
    Project Created
        ↓
    Project Explorer Updates
        ↓
    Live Preview Does Nothing

---

## Investigation

The project creation workflow was traced through `MainWindow` and `ProjectCreationManager`.

`ProjectCreationManager` was already opening the newly created project through `ProjectManager`.

For example, after creating a project, the manager performed:

```csharp
projectManager.OpenProject(
    projectPath
);
```

This meant that the application's current project was already being updated correctly.

The Project Explorer was also being refreshed after successful project creation through:

```csharp
RefreshProjectTree();
```

The Live Preview functionality itself was also already implemented.

`MainWindow` contained the existing:

```csharp
LoadDockedPreview()
```

method, which determined the appropriate preview URL and loaded it into `LivePreviewBrowser`.

The existing Open Project workflow already used this method correctly.

When an existing project was opened, the workflow was:

```csharp
projectManager.OpenProject(
    projectPath
);

RefreshProjectTree();

await LoadDockedPreview();
```

This immediately loaded the selected project into the docked preview.

The problem was that the New Project workflow did not follow the same pattern.

After successful project creation, `OpenNewProject()` ended with:

```csharp
projectCreationWindow?.SetComplete();

projectCreationWindow = null;

RefreshProjectTree();
```

The Project Explorer was therefore refreshed, but `LoadDockedPreview()` was never called.

The preview system wasn't broken.

The project wasn't failing to open.

The preview URL wasn't being generated incorrectly.

The application was simply never being told to refresh the docked preview after creating the new project.

---

## The Fix

The New Project workflow was updated so that the docked preview is loaded after the newly created project has been opened and the Project Explorer has been refreshed.

The existing code:

```csharp
projectCreationWindow?.SetComplete();

projectCreationWindow = null;

RefreshProjectTree();
```

was changed to:

```csharp
projectCreationWindow?.SetComplete();

projectCreationWindow = null;

RefreshProjectTree();

await LoadDockedPreview();
```

No changes were required to `ProjectCreationManager`.

No changes were required to `ProjectManager`.

No changes were required to the Live Preview system itself.

The missing connection was added to the UI workflow where it belonged.

The New Project workflow now follows the same pattern as opening an existing project:

```csharp
projectManager.OpenProject(
    projectPath
);

RefreshProjectTree();

await LoadDockedPreview();
```

This ensures that the newly created project becomes the active project in both the Project Explorer and the Live Preview.

---

## Verification

A new project was created through the New Project workflow.

The project creation process completed successfully.

The Project Explorer updated and displayed the newly created project.

The docked Live Preview then automatically loaded the new project without requiring any additional action.

The existing Open Project workflow continued to function as before.

The preview also correctly uses the project's `settings.wampds` configuration when a virtual host and domain are configured, while projects without a configured domain continue to use the PHP preview server where appropriate.

The complete workflow now behaves as expected:

    Create Project
        ↓
    Project Created
        ↓
    Project Opened
        ↓
    Project Explorer Refreshed
        ↓
    Docked Live Preview Loaded

---

## Result

This was another small issue caused not by a missing feature, but by a missing connection between existing features.

The project creation system was successfully creating and opening projects.

The Project Explorer was successfully updating.

The Live Preview was successfully capable of loading projects.

But the New Project workflow simply wasn't calling the method that connected the two.

The fix was one line:

```csharp
await LoadDockedPreview();
```

It was a tiny change, but it restored the expected workflow.

This is another example of why actually using WAMP-DS as a development environment is revealing issues that aren't necessarily obvious while building the individual components.

Everything can work correctly in isolation and still fail to produce the experience the developer expects when those components are used together.

The project was created.

The Explorer knew about it.

The preview just needed to be told.

One missing method call.

One small fix.

And creating a new project now leaves WAMP-DS ready to start developing immediately. 😄
