# Development Entry #07 - Editor Context Menu

**Date:** 17 August 2026  
**Area:** Code Editor / Developer Experience  
**Type:** Feature / Enhancement  
**Status:** Complete

---

## The Problem

While continuing real-world development inside WAMP-DS, another small usability issue became obvious during normal editor use.

The Code Editor had keyboard shortcuts for several common operations, but there was no context menu at all.

Right-clicking inside the editor did nothing.

This meant that although operations such as Find, Replace and Duplicate were already available through keyboard shortcuts, there was no familiar mouse-driven way to access them.

The workflow was essentially:

    Right-Click Editor
        ↓
    Nothing Happens
        ↓
    Remember Keyboard Shortcut

For a developer who prefers keyboard-driven editing this isn't necessarily a major problem.

But a code editor without a context menu feels incomplete.

Standard editing operations such as Cut, Copy, Paste and Select All are expected to be available through a right-click menu, and WAMP-DS-specific editor operations should be accessible there as well.

---

## The Existing Editor

WAMP-DS uses AvalonEdit as the underlying code editor.

The editor already supported several keyboard-driven operations:

    Ctrl + F
        ↓
    Find

    Ctrl + H
        ↓
    Replace

    Ctrl + D
        ↓
    Duplicate

These operations were already implemented inside `CodeEditor`.

The context menu therefore did not require new implementations of these features.

Instead, it could provide another way of accessing the functionality that already existed.

This was an important distinction.

The context menu should not create a second set of editor operations.

It should use the same underlying methods as the keyboard shortcuts.

---

## Adding The Context Menu

The context menu was added directly to the AvalonEdit control.

The initial menu contains the standard editing operations:

```xml
<ContextMenu
    x:Key="EditorContextMenu">

    <MenuItem
        Header="Cut"
        Command="ApplicationCommands.Cut"/>

    <MenuItem
        Header="Copy"
        Command="ApplicationCommands.Copy"/>

    <MenuItem
        Header="Paste"
        Command="ApplicationCommands.Paste"/>

    <Separator/>

    <MenuItem
        Header="Select All"
        Command="ApplicationCommands.SelectAll"/>

    <Separator/>

    <MenuItem
        Header="Find"
        Click="ContextFind_Click"/>

    <MenuItem
        Header="Replace"
        Click="ContextReplace_Click"/>

    <MenuItem
        Header="Duplicate"
        Click="ContextDuplicate_Click"/>

</ContextMenu>
```

The menu is then attached directly to the editor:

```xml
<avalonEdit:TextEditor
    x:Name="EditorTextBox"
    Background="{StaticResource EditorBackgroundBrush}"
    Foreground="#2B2520"
    FontFamily="Consolas"
    FontSize="14"
    ShowLineNumbers="True"
    WordWrap="False"
    HorizontalScrollBarVisibility="Auto"
    VerticalScrollBarVisibility="Auto"
    Padding="10"
    VerticalContentAlignment="Top"
    HorizontalContentAlignment="Left"
    LineNumbersForeground="#999999"
    ContextMenu="{StaticResource EditorContextMenu}"/>
```

This keeps the context menu associated specifically with the code editor rather than introducing application-wide menu behaviour.

---

## Using Existing Editor Commands

The standard editing operations use WPF's existing application commands.

For example:

```xml
<MenuItem
    Header="Cut"
    Command="ApplicationCommands.Cut"/>

<MenuItem
    Header="Copy"
    Command="ApplicationCommands.Copy"/>

<MenuItem
    Header="Paste"
    Command="ApplicationCommands.Paste"/>

<MenuItem
    Header="Select All"
    Command="ApplicationCommands.SelectAll"/>
```

This avoids unnecessarily implementing basic clipboard functionality inside WAMP-DS.

The framework already provides the appropriate commands.

WAMP-DS can simply expose them through the editor's context menu.

---

## Connecting WAMP-DS Features

The WAMP-DS-specific operations use the existing editor methods.

Three small event handlers were added:

```csharp
// ============================================================
// CONTEXT MENU
// ============================================================

private void ContextFind_Click(
    object sender,
    RoutedEventArgs e)
{
    ShowFindPanel();
}

private void ContextReplace_Click(
    object sender,
    RoutedEventArgs e)
{
    ShowReplacePanel();
}

private void ContextDuplicate_Click(
    object sender,
    RoutedEventArgs e)
{
    DuplicateCurrentLine();
}
```

This means the same functionality is now accessible through both keyboard and mouse interaction.

For example:

    Ctrl + F
        ↓
    ShowFindPanel()

or:

    Right-Click
        ↓
    Find
        ↓
    ShowFindPanel()

The implementation remains in one place.

---

## Keeping Keyboard And Mouse Behaviour Consistent

This was an important part of the implementation.

The context menu does not contain separate Find, Replace or Duplicate logic.

Instead:

```text
Keyboard Shortcut
        ↓
Existing Editor Method
```

and:

```text
Context Menu
        ↓
Existing Editor Method
```

Both paths therefore produce the same behaviour.

For Find:

```csharp
ShowFindPanel();
```

For Replace:

```csharp
ShowReplacePanel();
```

For Duplicate:

```csharp
DuplicateCurrentLine();
```

This keeps the Code Editor maintainable while allowing the same feature to be accessed in different ways.

---

## The Resulting Menu

The editor now provides a familiar right-click workflow:

    Right-Click
        ↓
    ┌─────────────────────┐
    │ Cut                 │
    │ Copy                │
    │ Paste               │
    ├─────────────────────┤
    │ Select All          │
    ├─────────────────────┤
    │ Find                │
    │ Replace             │
    │ Duplicate           │
    └─────────────────────┘

The menu is deliberately simple.

It does not attempt to reproduce every feature found in a large commercial IDE.

The goal is to provide the operations that are immediately useful within the existing WAMP-DS editor.

---

## Why This Matters

A context menu is a small feature.

It doesn't change the underlying editor.

It doesn't introduce a new development system.

But it changes how complete the editor feels.

A developer may remember `Ctrl+D`.

Another developer may naturally right-click and look for Duplicate.

Someone may want to paste code without remembering a keyboard shortcut.

Someone else may be working primarily with the mouse while navigating a project.

A good editor should accommodate those different interaction styles.

The important part is not whether the developer uses the mouse or keyboard.

The important part is that the operation is easy to reach.

---

## Real-World Development Again

Like several recent WAMP-DS improvements, this feature was not driven by a large specification.

It came from using the application.

While working inside the editor, the absence of a context menu became noticeable.

The thought was essentially:

> "Why can't I right-click this?"

That is exactly the sort of observation that becomes possible when the application is being used as an actual development environment rather than simply being tested as a collection of features.

The application itself becomes the test.

Normal development exposes the things that feel awkward.

Those things can then be fixed.

## Verification

The context menu was added to the editor and tested through normal interaction.

Right-clicking inside the editor now produces the expected menu.

The standard editing commands are available through the WPF application commands.

The WAMP-DS-specific commands correctly connect to the existing editor functionality.

The resulting workflows are:

    Right-Click
        ↓
    Find
        ↓
    Existing Find Panel

or:

    Right-Click
        ↓
    Replace
        ↓
    Existing Replace Panel

or:

    Right-Click
        ↓
    Duplicate
        ↓
    Existing Duplicate Logic

The existing keyboard shortcuts continue to work independently.

No existing Find, Replace or Duplicate functionality was replaced or duplicated.

## Result

The WAMP-DS Code Editor now has a proper context menu.

The menu provides standard editing operations alongside WAMP-DS-specific functionality.

The final editor interaction model now supports both keyboard and mouse access:

    Ctrl + F
        ↓
    Find

    Ctrl + H
        ↓
    Replace

    Ctrl + D
        ↓
    Duplicate

    Right-Click
        ↓
    Cut / Copy / Paste
    Select All
    Find
    Replace
    Duplicate

The implementation is intentionally small.

The existing editor functionality remains responsible for actually performing the operations, while the context menu simply provides another route into those features.

---

## The Bigger Picture

This is another example of a feature that would be easy to overlook when thinking about WAMP-DS purely in terms of its headline functionality.

Apache matters.

PHP matters.

MySQL matters.

SSL matters.

The project system matters.

The editor matters.

But once all of those pieces exist, the smaller interactions start becoming increasingly important.

A developer doesn't experience WAMP-DS as a list of features.

They experience it as a series of actions:

    Open Project
        ↓
    Edit Code
        ↓
    Save
        ↓
    Preview
        ↓
    Change Something
        ↓
    Edit Again

Every unnecessary interruption in that loop becomes friction.

The context menu removes one more small piece of it.

The editor can now respond naturally whether the developer reaches for the keyboard or the mouse.

This is becoming another recurring theme in the development of WAMP-DS.

The project isn't just about providing the tools needed to develop.

It's about making those tools behave in the way a developer expects them to behave.

Sometimes that means a complex feature.

Sometimes it means something as simple as:

> "I right-clicked the editor and expected a menu."

Now there is one.
