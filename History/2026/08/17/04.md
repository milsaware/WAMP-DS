# Development Entry #04 - Find and Replace Added to the Code Editor

**Date:** 17 August 2026  
**Area:** Code Editor / Developer Experience  
**Type:** Feature / Enhancement  
**Status:** Complete

---

## The Feature

As development inside WAMP-DS continued, another area of the Code Editor became worth improving: finding and replacing text.

A code editor without a convenient Find function quickly becomes frustrating, particularly when working with larger files.

The basic requirement was simple:

- `Ctrl+F` should open Find
- `Ctrl+H` should open Replace
- Searching should move through matches
- Match Case should be supported
- Replace should replace the current match
- Replace All should replace every match
- `Escape` should close the search interface

However, the goal was not simply to add a couple of text boxes and call the feature finished.

The Find and Replace interface needed to feel like part of WAMP-DS.

---

## The Existing Editor

WAMP-DS already uses AvalonEdit as the underlying code editor.

AvalonEdit provides a number of useful editor capabilities, including syntax highlighting, text selection and document manipulation.

The editor therefore already had the foundation required to implement searching and replacing.

However, the desired experience required more control over how the functionality appeared and behaved.

Rather than opening a completely separate window for Replace, the intention was to have Replace extend the existing Find interface.

The result should feel like one editor feature rather than two unrelated dialogs.

---

## Designing the Interaction

The intended workflow became:

    Ctrl + F
        ↓
    Find interface appears
        ↓
    Search for text
        ↓
    Press Enter to find the next match

and:

    Ctrl + H
        ↓
    Find interface expands
        ↓
    Replace controls appear
        ↓
    Replace / Replace All

This meant that Find and Replace could share the same interface.

When Replace mode was activated, the additional controls would simply be added to the existing Find interface rather than opening another window.

That small distinction makes the editor feel considerably more cohesive.

---

## Keyboard Shortcuts

The first part of the implementation was handling the editor shortcuts.

`Ctrl+F` was assigned to the Find interface:

```csharp
if (
    e.Key == Key.F &&
    Keyboard.Modifiers == ModifierKeys.Control
)
{
    ShowFindPanel();

    e.Handled = true;

    return;
}
```

`Ctrl+H` was then assigned to Replace:

```csharp
if (
    e.Key == Key.H &&
    Keyboard.Modifiers == ModifierKeys.Control
)
{
    ShowReplacePanel();

    e.Handled = true;

    return;
}
```

Escape was also handled so the search interface could be dismissed without requiring the mouse:

```csharp
if (
    e.Key == Key.Escape &&
    SearchPanel.Visibility ==
    Visibility.Visible
)
{
    CloseSearchPanel();

    e.Handled = true;
}
```

This made the feature usable entirely from the keyboard.

---

## Find

The Find functionality searches the current document from the position immediately after the current selection.

The search respects the Match Case option.

The comparison is selected using:

```csharp
StringComparison comparison =
    MatchCaseCheckBox.IsChecked == true
        ? StringComparison.Ordinal
        : StringComparison.OrdinalIgnoreCase;
```

The document is then searched for the next occurrence:

```csharp
int index =
    documentText.IndexOf(
        searchText,
        start,
        comparison
    );
```

If there are no more matches after the current position, the search wraps back around to the beginning of the document.

This allows repeated searches to cycle through the entire file rather than stopping permanently at the end.

When a match is found, it is selected in the editor and the relevant line is brought into view.

---

## Using the Current Selection

Another small usability improvement was added when opening Find or Replace.

If text is already selected in the editor, that selection is automatically placed into the Find box.

For example:

```csharp
if (!string.IsNullOrEmpty(
    EditorTextBox.SelectedText
))
{
    FindTextBox.Text =
        EditorTextBox.SelectedText;

    FindTextBox.SelectAll();
}
```

This means that selecting a piece of code and pressing `Ctrl+F` immediately prepares that text for searching.

It removes another unnecessary step from the workflow.

---

## Replace

Replace mode builds on the existing Find functionality.

When `Ctrl+H` is pressed, the Replace row becomes visible:

```csharp
ReplaceRow.Visibility =
    Visibility.Visible;

ReplaceButton.Visibility =
    Visibility.Visible;

ReplaceAllButton.Visibility =
    Visibility.Visible;
```

The Find and Replace interfaces therefore occupy the same area of the editor.

There is no second window.

There is no modal dialog.

The editor simply gains the additional controls required for the operation.

---

## Replace One

The Replace operation first checks whether the current selection is the text being searched for.

If it isn't, the next matching occurrence is selected.

If it is, the selected text is replaced directly in the AvalonEdit document:

```csharp
EditorTextBox.Document.Replace(
    EditorTextBox.SelectionStart,
    EditorTextBox.SelectionLength,
    replace
);
```

The search then continues to the next occurrence.

This produces the expected workflow:

    Find Match
        ↓
    Replace
        ↓
    Find Next Match
        ↓
    Replace
        ↓
    Continue

---

## Replace All

Replace All required a slightly different approach.

Rather than relying on the current selection, the document is searched from the beginning.

Each matching occurrence is replaced and the search position is advanced by the length of the replacement text.

```csharp
int position = 0;

while (true)
{
    string documentText =
        EditorTextBox.Text;

    int index =
        documentText.IndexOf(
            find,
            position,
            comparison
        );

    if (index < 0)
        break;

    EditorTextBox.Document.Replace(
        index,
        find.Length,
        replace
    );

    position =
        index +
        replace.Length;
}
```

Advancing the position by the replacement length is important because the replacement may be a different length from the original search text.

This prevents the operation from repeatedly processing the same replacement.

---

## Keyboard Navigation

The Find box also responds directly to Enter and Escape.

Pressing Enter performs the next search:

```csharp
if (e.Key == Key.Enter)
{
    FindNext();

    e.Handled = true;

    return;
}
```

The Replace box similarly allows Enter to perform the Replace operation:

```csharp
if (e.Key == Key.Enter)
{
    ReplaceButton_Click(
        ReplaceButton,
        new RoutedEventArgs()
    );

    e.Handled = true;

    return;
}
```

Escape closes the interface from either box.

The result is that the complete workflow can be performed without leaving the keyboard.

---

## Styling the Interface

The functionality was only part of the work.

The Find and Replace controls also needed to match the existing WAMP-DS interface.

The search interface uses the same dark editor-panel styling used elsewhere in the application.

The Find and Replace boxes were designed to appear as part of the editor rather than as standard WPF controls that had simply been dropped into the application.

The Replace controls also expand from the existing Find interface rather than appearing as a separate dialog.

This was an important part of the implementation.

The feature needed to be functional **and** feel like it belonged in WAMP-DS.

---

## Verification

The completed Find and Replace functionality was tested through normal editor use.

The following workflows were verified:

    Ctrl + F
        ↓
    Find panel opens

    Ctrl + H
        ↓
    Replace controls appear

    Enter
        ↓
    Next match selected

    Match Case
        ↓
    Search comparison changes

    Replace
        ↓
    Current match replaced

    Replace All
        ↓
    All matching occurrences replaced

    Escape
        ↓
    Search interface closes

Existing selected text is also automatically placed into the Find field when the interface is opened.

The Find and Replace controls can therefore be used as part of the normal editing workflow without interrupting development.

---

## Result

What started as a relatively simple requirement — adding Find and Replace — turned into a fairly involved editor enhancement.

The implementation required:

- Keyboard shortcut handling
- Find and Replace state management
- Search wrapping
- Case-sensitive and case-insensitive comparisons
- Selection handling
- Document replacement
- Replace All logic
- Keyboard navigation
- Closing behaviour
- Dynamic expansion of the interface
- Integration with AvalonEdit
- Custom WAMP-DS styling

The important part is that Replace doesn't feel like a separate feature bolted onto the editor.

It extends Find.

Press `Ctrl+F` and the Find interface appears.

Press `Ctrl+H` and the same interface expands to provide Replace.

Everything happens in place.

That makes the feature feel considerably more natural to use.

This is exactly the sort of functionality that can look trivial from the outside but turns into a surprisingly involved piece of work once all of the small details are considered.

And that's becoming a recurring theme with WAMP-DS.

The big features are important.

But it's the little interactions that determine whether the software actually feels good to use.
